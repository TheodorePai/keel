# 运行产物

`work/.local/` 只保存允许丢失的主动运行产物，不进 Git。它不是备份，也不是正式资产区；生成方式不决定保留价值。

## 放置与保留

- 可丢弃的日志、下载中间件、调试页面、临时导出和可接受重建成本的缓存放 `.local/`。
- 唯一实验记录、人工标注、需要保留的 checkpoint、正式交付物放 `work/` 的所属目录；需要长期留存的过程证据放对应笔记的 `assets/`，超过大小限制时登记为资产。
- `keel asset add` 拒绝 `.local/` 中的所有正式资产，包括只能靠备份恢复的 `local` 类型。先把文件移到所属目录，再登记；`local` 类型仍需另有备份。
- 正式笔记不能链接 `.local/` 文件。先转存成果或证据，再引用稳定路径。仅在行内代码或示例中说明运行路径不受此限制。
- 一次性脚本用完即删；仍有复用价值的脚本归入所属项目或 skill，需要保留的实验脚本随笔记附件保存。

## 并行与缓存

- 主动输出使用 `work/.local/<任务ID>/<运行ID>/`，每次运行使用新目录；不要用多个任务共同写入的 `latest` 或固定文件名传递结果。任务和进度仍只进 Beads。
- 每次运行记录输入摘要、代码版本（包含未提交改动的摘要）、参数、工具版本和执行命令；这些运行元数据随产物保存即可。
- 缓存复用前核对这些条件；条件缺失或不匹配就重新生成。不要只凭文件存在或目录名认定有效。
- 同一工作区切分支会留下 `.local/`；新 worktree 或 clone 不会自动复制它。缺失时按已保存的输入与命令重建，不隐式借用其他工作区的可写缓存。

## 工具默认目录

`node_modules/`、`.venv/`、`__pycache__/`、工具构建目录等由工具管理的依赖、缓存和中间产物，可以保留默认位置并加入项目 `.gitignore`。不为统一目录强行搬迁或共享可写依赖；工具支持指定主动导出位置时使用 `.local/`。需要交付的构建结果仍按正式资产保存。

## 运行结束与任务收尾

运行目录的 `.run.json` 只记录文件生命周期，任务状态仍在 Beads。用 `keel local run <任务ID>/<运行ID> running --pid <PID>` 为新目录创建记录及 `.active`；PID 应是实际生产进程或负责等待所有子服务退出的监督进程。默认记录调用 Keel 的父进程，适合由一个 shell 管理整次运行。目录必须全新，不认领已有输出；完成后不能再次运行，重跑使用新的运行 ID。

一次运行结束，Agent 按顺序执行：

1. 把需要交付的成果转存到 `work/` 所属目录，把需要留存的证据转存到笔记附件，按需更新资产登记和稳定链接。
2. 停止本次运行的服务、后台子进程和监听端口，确认负责生产的进程已退出。仅主命令返回、日志停止更新或 `.active` 很旧都不能证明所有服务已停止。
3. 在另一次命令调用中运行 `keel local run <任务ID>/<运行ID> completed`。Keel 核对 PID 和启动时间；进程仍活着或无法核对时拒绝完成。记录完成时间并解除匹配的 `.active`。
4. 已转存并允许丢失的目录标记为 `disposable`。暂需保留时用 `retained --reason "等待结果复查" --review-on YYYY-MM-DD`；原因和复查日期写入 `.keep`。复查到期只提醒，重新声明 `disposable` 才解除命令创建的保留。旧手写标记先核查，不自动移除。
5. 用 `keel local clean <任务ID>/<运行ID>` 查看保留原因；需要执行回收时加 `--apply`。清理仍遵守完成后的保留期和近期写入保护，不能因本次任务结束就删除未到期产物。

任务关闭前，Agent 核对本任务每次运行：成果已转存、生命周期已声明、服务已停止，再清理已符合条件的运行目录。父任务目录只是容器，不用一个状态覆盖多个运行；不要用整棵任务目录绕过逐次运行的保护。保留未到期或状态不明的目录，在任务收尾记录中说明原因。中断或失效 `.active` 先视为状态不明，检查产物与服务后明确完成；不根据进程退出自动推断成果可丢弃。

## 自动触发与项目预算

运行产物管理支持 Windows、Linux 和 macOS。Windows 使用本地 Win32 文件锁及进程创建时间，查询进程不会向生产进程发送信号；POSIX 继续使用 `flock` 和系统报告的进程启动时间。记录格式保持不变，但进程身份只在原平台核对；来自其他平台或权限不足而无法确认的记录继续保留，不自动认领或删除。

Windows 仅支持普通本地磁盘路径，不支持 UNC 网络路径或设备路径；运行目录、管理目录及其祖先不能是重解析点（包括 junction 和符号链接）。清理不会进入运行目录内的链接目标；删除时以打开的文件句柄核对目录身份，目标被替换或无法安全访问时停止。请把 `.local/` 放在实际本地目录中，不能通过链接指向其他位置。

开始项目工作运行 `keel local sweep --daily`；普通工作区的 `keel check`、`keel status` 也调用同一入口。每个工作区按本机日期最多检查一次，进程锁防止并行 Agent 重复回收；中断后释放锁，检查失败不会记录成功日期。`keel local sweep` 可立即重查。没有常驻后台进程；项目闲置时不扫描。`--staged`、`--ref`、`--since` 保持只读，不触发维护。

默认保留完成后 30 天；需要项目差异时，在 `keel.toml` 设置：

```toml
[local]
retention_days = 30
budget_mb = 1024
```

`retention_days` 用于控制完成后的留存窗口；`budget_mb` 用于发现项目运行产物的容量压力，不设通用硬额度。不填预算仍执行过期回收并显示占用。超预算只清理已经符合保留期与安全条件的目录；其余保留并提醒，不能因此提前删除。每天的状态记录与管理锁位于 `.local/.keel/`，不得手动当作运行目录清理。没有记录的旧目录始终只提示，不自动迁移或认领。

## 清理记录

实际清理与自动检查在 `.local/.keel/cleanup.jsonl` 留下删除意图、删除结果、文件字节数和保留原因；预览不写清理日志。删除前先写日志，再核对路径、状态、标记、资产和 Git 跟踪内容。日志无法安全读取或写入就停止删除。中途退出可能只留下 `delete_started`；`delete_incomplete` 表示删除未完成，需检查剩余内容，不能当作已释放空间。

日志只保留最近 200 条，且总大小最多 256 KiB；超限淘汰最旧记录，不创建无限轮转文件。一次大型回收的较早明细也可能被淘汰，需要长期证据时转存到笔记附件。字节数是文件逻辑大小，不承诺文件系统实际释放块数。状态、日期和锁文件只维护当前值，不追加历史。原子写入每个记录只用一个固定 `.pending` 文件；异常退出留下它时停止后续写入并提示核查，避免临时日志无限累积。

## 检查失败与清理

- `keel local status` 显示一级条目大小及活动、保留复查提醒。
- `keel local clean <任务ID>/<运行ID> --older-than 30` 默认预览；核对后加 `--apply` 执行。保留期从记录中的完成时间计算；最近 24 小时有写入或完成后仍有写入的目录继续保留，先检查后用新运行目录重跑。
- 只有已完成且明确声明 `disposable` 的目录有资格回收。旧目录、无效记录、仍登记为资产或被 Git 跟踪的内容、`.keep` 和 `.active` 都受保护；不跟随软链接，不删除整个 `.local/`。
- `local-tracked`：用 `git rm --cached -- <文件>` 移出 Git 跟踪并保留本机内容；先核对路径，不直接删除成果。已经进入历史的副本不会因此消失。
- `local-ignore`：运行 `keel init` 补齐项目 `.gitignore` 中的 `work/.local/`，并检查后面的反向规则。全局忽略或 `.git/info/exclude` 不能替代项目规则。
- `asset-local` / `local-link`：先把需要保留的内容移到所属资产目录或笔记附件，再更新资产清单或链接；已有 `.local/` 内容不会自动移动或删除。
- 清理前核对需要保留的成果、证据和仍在运行的服务，先转存后清理明确的任务目录。不要把整个仓库的忽略文件当作垃圾统一删除；工具依赖和本机资产也可能被忽略。

用 `keel check` 和 `keel check --staged` 确认工作区与实际提交都符合边界。
